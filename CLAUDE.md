# Офис агентов — инструкции для Claude Code

Вы находитесь в репозитории «Офис агентов». Обычно владелец просит изменить **состав и обязанности агентов**, научить агента **выполнять определённую работу** (бриф или навык), добавить задачу **в расписание** (сценарий) либо изменить **доступные подключения**. Для таких запросов редактируйте описанные ниже JSON-файлы и папки. Не меняйте `src/`, `serve.mjs` или сборку, если пользователь прямо не просит изменить код продукта.

## Изменение агентов

Состав хранится в `office.agents.json` (поставляемые значения) и `office.agents.local.json` (локальные настройки, игнорируются Git). **Всегда записывайте пользовательские изменения в `office.agents.local.json`**. Если файла нет, создайте `{"agents": []}` и добавляйте только изменяемых агентов. Не редактируйте `office.agents.json`, если пользователь не просит изменить поставляемые значения.

```json
{ "id": "newt", "department": "marketing", "lead": false,
  "name": "РЕДАКТОР РАССЫЛКИ", "role": "Агент подготовки рассылок",
  "does": "Готовит ежемесячную рассылку, которую действительно читают подписчики.",
  "tools": ["beehiiv", "loops"],
  "brief": "Пять тезисов и одна яркая цитата. Тема короче 40 символов. Не начинай с названия компании." }
```

Можно изменять **name, role, does, tools, brief, model, effort**. `name` должно быть коротким и в верхнем регистре. `does` — описание работы в одном-двух предложениях, которое агент читает перед каждой задачей. `tools` — названия подключений как в верхней панели, в нижнем регистре. `brief` — постоянные инструкции конкретному агенту, до 2 000 символов, строка или массив строк. Если нужны этапы и шаблон, создайте навык.

`model`: `sonnet`, `opus`, `fable` или пустое значение для модели офиса. `effort`: `low`, `medium`, `high`, `xhigh`, `max` или пустое значение. Задавайте их только по прямой просьбе владельца. Приоритет: задача → сценарий → агент → офис → значение модели.

Состав читается в порядке, где более поздний источник важнее: `office.agents.json` → `<brain>/Agents Office/agents.json` → `office.agents.local.json`. `<brain>` — папка из `brain` в `office.config.local.json` или `office.config.json`. Если владелец хранит состав в Базе знаний, записывайте изменения туда.

Поля `id`, `department`, `lead` неизменяемы. В офисе **шесть отделов и 35 мест**. Не добавляйте и не удаляйте агентов, отделы или секции. Для нового типа агента переименуйте подходящее место.

Ключи отделов: `emails` (5), `sales` (6), `marketing` (7), `ops` (6), `fin` (4), `delivery` (7). Руководитель каждого отдела должен оставаться руководителем.

После изменения выполните `npm run check`, исправьте ошибки и попросите владельца перезапустить офис командой `npm start`.

## Обучение агента: навыки

Фразы «вот как мы делаем X», «пусть агент делает так», «вот наш регламент, шаблон или хороший пример» означают, что нужен **навык**. Это папка с `SKILL.md` и сопутствующими файлами, совместимая с навыками Claude Code. Перед первым созданием полностью прочитайте `SKILLS.md`.

**Куда записывать:** `<brain>/Agents Office/skills/<name>/SKILL.md`. Не помещайте пользовательские навыки в репозиторную папку `skills/`: там лежат примеры, которые может изменить `git pull`. Навык с тем же именем в Базе знаний заменяет поставляемый.

Если инструкция умещается в абзац без этапов и шаблона — это `brief`. Если есть процесс, структура результата, правила или документ-образец — это навык. До записи выясните условие применения, исходные материалы, структуру результата и правила. Полностью прочитайте предоставленные документы. Если важной информации нет, задайте один вопрос; не придумывайте процесс владельца.

```text
<brain>/Agents Office/skills/proposal/
  SKILL.md       метаданные и инструкции, до 6 000 символов
  template.md    структура результата
  example.md     удачный реальный пример, необязательно
```

```markdown
---
name: proposal
description: Как мы готовим предложение клиенту
agents: [piper]
---
# Подготовка предложения
Используй навык для запроса, результат которого клиент принимает или отклоняет.

## Перед началом
1. Прочитай данные клиента и `10-Business/offer-ladder.md`.
## Структура
Следуй `template.md` раздел за разделом.
## Правила
- Краткие и абсолютные правила, по одному на строку.
```

**Привязка:** `agents: [id, id]` связывает навык с агентами из `office.agents.json`; выберите место с подходящим `does` и сообщите о выборе. `departments: [emails]` связывает навык со всем отделом. Отсутствие обоих полей означает всех агентов — допустимо только для общего стиля. Неизвестные идентификаторы отклоняются.

Ограничения: тело `SKILL.md` — 6 000 символов; каждый соседний файл — 4 000, все вместе — 8 000. Читаются `.md`, `.txt`, `.csv`, `.json`, `.yaml`, `.html`; остальные файлы перечисляются по имени. Длинные материалы храните обычными заметками, а в навыке ссылайтесь на них.

Первая строка после заголовка описывает условие применения. Затем идут этапы, структура и правила. Ссылайтесь на заметки по имени. Один вид работы — один навык. Не фиксируйте число, которое должно браться из реестра; укажите источник.

После записи выполните `npm run check`. Навыки и брифы действуют со следующей задачи без перезапуска. Сообщите владельцу путь, привязанного агента и пример задачи. Постоянные замечания из `доработай: …` затем включайте в навык.

Проверка через `http://localhost:4520/api/skills` или:

```bash
node -e "import('./skills.mjs').then(async m=>console.log(JSON.stringify(m.loadSkills((await import('./config.mjs')).loadConfig().brainPath,(await import('./roster.mjs')).loadRoster().agents).summary(),null,1)))"
```

## Уроки и установочное интервью

- **Исправления:** `<brain>/Agents Office/feedback/<agent-id>.md`. Каждое `доработай: …` сохраняется как постоянное правило (`## Standing rules`) или разовое замечание (`## One-offs`). По просьбе включить уроки в навык перенесите устойчивые предпочтения в навык либо бриф и удалите перенесённые строки. Не придумывайте правил.
- **Интервью:** команда «настроить» запускает `onboard.mjs`. Брифы пишутся в `<brain>/Agents Office/agents.json`, навык — в `<brain>/Agents Office/skills/<name>/`. Прежний одноимённый файл сохраняется как `SKILL.md.backup-<time>`. Незавершённое интервью хранится в `data/interviews.json`.

## Сценарии: задачи по расписанию

Фразы «каждый понедельник», «по утрам», «по расписанию», «автоматически в…» означают **сценарий**. Сейчас сценарии доступны только для Почты, Финансов и Продаж (`emails`, `fin`, `sales`). Для других отделов сообщите, что функция появится позже, и не записывайте сценарий.

Путь: `<brain>/Agents Office/routines.json`. Если файла нет, создайте `{"routines": []}`.

```json
{ "id": "overdue-reminders", "dept": "fin", "agent": "invo",
  "title": "Составить список просроченных счетов и черновики напоминаний",
  "text": "Проверь просроченные счета в Xero и подготовь черновики в Gmail.",
  "when": { "kind": "weekly", "days": [1], "at": "09:00" },
  "needsOk": true, "paused": false }
```

- `id` — короткий уникальный идентификатор; `dept` — один из трёх отделов; `agent` — агент этого отдела.
- `text` — формулировка владельца; `title` — карточка до 90 символов.
- `when`: `daily`, `weekdays`, `weekly` с `days` (0 — воскресенье), `hourly` либо `minutes` для демонстрации. Время местное, 24-часовое.
- `when.start: "YYYY-MM-DD"` необязательно задаёт дату начала.
- `needsOk` по умолчанию `true`: внешние действия ждут одобрения. Отключайте только для чтения и отчётов и объясняйте почему.
- `paused: true` оставляет сценарий в расписании без запуска.
- `model` и `effort` задавайте только по просьбе владельца.
- `team: true` означает командную работу; владельцем сценария становится руководитель отдела.

Сервер перечитывает файл каждые 20 секунд. Состояние находится в `data/routines.json`. После изменения выполните `npm run check` и сообщите название, расписание, агента, необходимость одобрения и наличие кнопки «ЗАПУСТИТЬ».

## Разовая задача на дату

«В пятницу…» или «в следующий вторник в 10…» без слова «каждый» — разовая запланированная задача. Пользователь создаёт её в календаре клавишей **P**, либо интерфейс отправляет `{ "dept", "text", "at": <ms или ISO> }` в `/api/tasks`. Отдельного файла конфигурации нет; данные хранятся в `data/tasks.json` со статусом `scheduled`.

## Подключения

Верхняя панель показывает MCP-серверы из `claude mcp list`. Новое подключение добавляется через `claude mcp add …` или claude.ai. Доступ регулируется в `office.config.local.json` или `office.config.json`:

```json
"mcp": {
  "allow": [],
  "deny": ["Stripe"],
  "departments": { "Slack": ["emails", "ops"] }
},
"tools": { "web": true, "browser": true },
"teams": { "enabled": true, "max": 4 }
```

Пустой `allow` разрешает все подключённые серверы. `deny` показывает сервер на панели, но не выдаёт агентам; здесь же можно указать `Chrome`. `departments` ограничивает сервер отделами. `tools.web` включает веб-поиск. `tools.browser` даёт доступ к браузеру владельца через Claude in Chrome и требует один раз выполнить `claude --chrome`. `teams.enabled` показывает кнопку «КОМАНДА», `teams.max` ограничивает число участников значением 2–6.

Агенты не получают Bash, файловые инструменты или субагентов. Правило: читать можно свободно; отправлять, публиковать, платить, удалять или менять внешние данные разрешено **только когда задача владельца прямо требует этого действия**.

## Команды агентов

По фразе «всей командой», «подключи команду» или кнопке «КОМАНДА» руководитель делит задачу между двумя–`teams.max` подходящими местами. Участники работают параллельно и оставляют заметки `@lead: …` или `@<id>: …`; руководитель собирает итог. Это собственная реализация офиса на headless-сеансах Claude, а не интерактивные Agent Teams Claude Code. Для улучшения распределения уточняйте `does` и навыки. Командный сценарий задаётся `"team": true` и принадлежит руководителю.
